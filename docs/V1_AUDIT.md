# V1 코드 감사

작성일: 2026-09-08
감사 대상: `main`, `codex/badminton-v1`, `codex/adsense-progress`
감사 방식: 브랜치를 전환하지 않고 Git 객체를 읽는 방식으로만 확인

## 1. 결론

V1은 React 18 + Vite 기반의 단일 페이지 앱이며, Express 서버가 정적 파일과 일부 API를 함께 제공합니다. 배드민턴 스케줄러처럼 독립성이 높은 계산 로직은 품질이 좋고 테스트도 있으므로 보존 가치가 있습니다. 반면 V2가 목표로 하는 검색 유입, 개별 콘텐츠 공유, 누적 투표, 랭킹, 운영자 CMS를 지탱할 영속 데이터 계층과 서버 렌더링 구조는 없습니다.

V1 전체를 계속 확장하는 것보다 V2를 새 구조로 만들고 검증된 순수 로직만 선별 이관하는 편이 위험이 낮습니다.

## 2. 현재 구조

| 영역 | 현재 구현 | 판정 |
| --- | --- | --- |
| 프런트엔드 | React 18, TypeScript, Vite, Wouter | 게임 UI 참고 가능, V2 기반으로는 교체 |
| 렌더링 | 모든 경로에 같은 `index.html`을 보내는 CSR | 콘텐츠 SEO 목표에 부적합 |
| 서버 | Express 4, 개발/운영 서버 구현이 별도 | 일부 동작이 환경마다 달라 교체 권장 |
| 데이터 | `MemStorage`, JSON 파일, `localStorage` | 누적 투표·랭킹·CMS에 부적합 |
| DB | Drizzle 스키마와 설정은 있으나 런타임 미연결 | 개념만 참고하고 새 마이그레이션 작성 |
| 인증 | 관련 패키지만 설치, 실제 인증 흐름 없음 | 새로 구현 |
| 파일 저장 | Replit sidecar 전용 GCS 연동 흔적 | 배포 환경 중립 어댑터로 교체 |
| 테스트 | 배드민턴 로직 테스트 2개 | 해당 기능 보존, 핵심 V2 테스트 추가 필요 |
| CI | 타입 검사와 빌드만 수행, 테스트 미실행 | 교체 필요 |
| 배포 | 빌드 워크플로만 있고 실제 배포 단계는 주석 | 운영 배포 기준을 새로 확정 |

## 3. 사용자 기능 감사

### 퀴즈

- 연예인 데이터는 파일명이 256을 암시하지만 실제 레코드는 20개입니다.
- 서버에서 무작위 항목을 받아 브라우저에서 진행합니다.
- 결과와 이용 기록이 서비스 전체 통계로 축적되지 않습니다.
- 데이터 출처, 이미지 사용 권리, 검수 상태를 기록하는 필드가 없습니다.

### 취향 월드컵

- 생성, 직렬화, 라운드 진행, 개인 결과 순위 계산이 구현돼 있습니다.
- 8/16/32/64강을 지원하지만 기획 P0는 16/32강에 집중합니다.
- 제작물과 현재 게임은 `localStorage` 및 긴 공유 URL에 의존합니다.
- 현재 순위는 한 번의 플레이 안에서만 계산되며 전체 사용자 투표 집계가 아닙니다.
- 공개 상태, 검수 상태, 신고, 태그, 설명, 작성자, 집계 테이블이 없습니다.

### 배드민턴 대진표

- 730줄 규모의 스케줄러에 휴식 간격, 중복 배정, 반복 매칭, 코트 수 검증이 구현돼 있습니다.
- 세션 버전 관리와 손상 데이터 방어 테스트가 있습니다.
- 브라우저 저장 방식이지만 단독 도구로는 완결성이 가장 높습니다.
- V2 콘텐츠 플랫폼과 결합하지 않고 `codex/badminton-v1`에서 독립 보존하는 현재 결정이 적절합니다.

## 4. SEO·공유·콘텐츠 품질

- 모든 경로가 동일한 정적 HTML 메타데이터로 시작하고, 페이지별 메타데이터는 브라우저 실행 후 수정됩니다.
- 콘텐츠별 고유 서버 HTML, 안정적인 canonical, 동적 OG 이미지가 없습니다.
- 사이트맵은 수동 XML이며 실제 콘텐츠 데이터와 연결되지 않습니다.
- `robots.txt`가 없습니다.
- 홈과 플레이 화면 중심이라 검색 사용자가 읽을 수 있는 설명, 비교 기준, 결과 해설이 충분하지 않습니다.
- `codex/adsense-progress`에는 소개·문의·정책·가이드 페이지, `ads.txt`, 로고, 푸터, 광고 제거 작업이 별도로 보존돼 있습니다. 이를 V2에 그대로 복사하지 말고 문구와 URL을 새 정보 구조에 맞춰 선별 이관합니다.

## 5. 데이터·운영 감사

- `shared/schema.ts`와 `shared/quiz-schema.ts`에 세션 모델이 중복됩니다.
- PostgreSQL 설정은 있으나 실제 서버 저장소는 메모리 구현입니다.
- 운영 서버 재시작 시 퀴즈 세션과 배드민턴 API 데이터가 사라집니다.
- 콘텐츠 생성·수정·게시·숨김을 수행할 관리자 화면이 없습니다.
- 조회, 시작, 완료, 공유, 투표 전환을 측정하는 분석 이벤트가 없습니다.
- 신고 접수와 처리 이력 모델이 없습니다.

## 6. 보안·안정성 감사

출시 전에 V1 서버 코드를 그대로 재사용해서는 안 됩니다.

- 외부 URL을 서버가 대신 가져오는 이미지 프록시는 목적지 제한이 없어 내부 주소 접근 위험이 있습니다.
- 이미지 일괄 이관 API가 인증 없이 공개돼 있습니다.
- 세션 수정 API는 요청 본문 검증과 소유권 검사가 부족합니다.
- 투표 중복 방지, 속도 제한, 봇 완화가 없습니다.
- 객체 저장소 코드는 Replit 로컬 sidecar 주소에 결합돼 있고 ACL 그룹 구현이 비어 있습니다.
- 개발 서버와 단순 운영 서버의 API 목록이 달라 환경별 동작 불일치 가능성이 있습니다.

## 7. 재사용 판정

### 그대로 보존 후 테스트를 보강할 후보

- `client/src/lib/badminton-scheduler.ts`
- `client/src/lib/badminton-session.ts`
- 배드민턴 관련 테스트

이 항목들은 V2가 아니라 `codex/badminton-v1`의 독립 제품 자산입니다.

### 인터페이스를 바꿔 이관할 후보

- `worldcup-logic.ts`의 라운드 진행과 순위 계산
- 일부 UI 토큰과 접근성 패턴
- AdSense 진행 브랜치의 소개·문의·정책 페이지 주제와 푸터 정보 구조

월드컵 로직은 `Date.now()`와 `Math.random()`을 주입 가능한 함수로 바꾸고, 신뢰할 수 없는 직렬화 데이터 검증을 강화한 뒤 테스트와 함께 이관합니다.

### 폐기 또는 새로 구현할 영역

- Wouter 라우팅과 Vite SPA 셸
- 메모리 저장소와 중복 Drizzle 스키마
- 공개 이미지 프록시 및 무인증 마이그레이션 API
- Replit 전용 객체 저장소 연결
- 클라이언트 메타 태그 변경 방식
- 수동 사이트맵과 환경별로 갈라진 Express 서버

## 8. 브랜치별 역할

| 브랜치 | 역할 | V2 사용 방식 |
| --- | --- | --- |
| `main` | V1 전체 원본 | 감사 및 선택적 로직 출처 |
| `codex/badminton-v1` | 배드민턴 단독 제품 보관 | 독립 유지, V2에 결합하지 않음 |
| `codex/adsense-progress` | 광고 제거·정책/UI 보완 완료분 | 내용과 설계만 선별 이관 |
| `codex/adsense-next` | 광고 검토 전 남은 작업 | V2 출시 체크리스트 입력 |
| `codex/v2` | 새 콘텐츠 플랫폼 | V1 의존 없이 새 이력 유지 |

## 9. 즉시 필요한 결정

1. V2 프레임워크는 Next.js App Router로 확정합니다.
2. 운영 데이터의 기준 저장소는 PostgreSQL로 단일화합니다.
3. 관리자만 콘텐츠를 발행하고, 일반 사용자 제작은 P1 이후 검토합니다.
4. 익명 투표는 서명된 세션 식별자와 서버 측 중복 키를 사용합니다.
5. 광고는 게시자 콘텐츠와 동의 관리가 갖춰진 공개 상세 화면에만 제한합니다.
