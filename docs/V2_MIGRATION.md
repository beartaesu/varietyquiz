# V2 이관 계획

작성일: 2026-09-08

## 원칙

V2는 `codex/v2`의 독립 이력을 유지합니다. V1 브랜치를 합치지 않고 필요한 파일의 개념과 검증된 로직만 출처를 기록해 옮깁니다. 데이터 이관은 항상 `추출 → 검증 → 변환 → 미리보기 → 적용 → 대조` 순서로 진행합니다.

## 단계

### 0. 보존선 확정 — 완료

- V1 원본: `main`
- 배드민턴 단독본: `codex/badminton-v1`
- AdSense 완료 작업: `codex/adsense-progress`
- AdSense 남은 작업: `codex/adsense-next`
- V2 독립 시작점: `codex/v2`

기존 stash는 삭제하지 않습니다. 각 보존 브랜치와 내용이 일치하는지 최종 확인한 뒤 별도 정리 작업으로만 제거합니다.

### 1. 기반 교체

현재 V2의 최소 Vite 셸을 Next.js App Router 프로젝트로 교체합니다. 이때 홈 한 페이지, 오류 페이지, 스타일 토큰, 타입 검사, 단위 테스트, CI를 먼저 통과시킵니다.

완료 조건:

- 개발·빌드·타입 검사·테스트 명령이 문서화돼 있다.
- 서버 컴포넌트 홈이 렌더링된다.
- CI가 네 명령을 실제로 실행한다.
- 환경 변수 예제가 비밀값 없이 제공된다.

### 2. 데이터 기반

PostgreSQL 스키마와 순방향 마이그레이션을 만듭니다. 개발 시드에는 권리가 명확한 텍스트·자체 제작 이미지만 사용합니다.

완료 조건:

- 빈 DB에서 마이그레이션과 시드가 재현된다.
- 발행 상태와 관계 제약을 DB가 보장한다.
- 투표 원본으로 집계를 재생성할 수 있다.
- 백업·복원 연습 절차가 있다.

### 3. 읽기 경로

홈, 상세, 카테고리, 태그, 결과, 랭킹을 실제 DB 데이터로 서버 렌더링합니다. 이 단계까지 쓰기 기능은 관리자 시드 명령으로 제한할 수 있습니다.

### 4. 참여 경로

VS부터 익명 투표·중복 완화·집계를 완성한 뒤 월드컵 16/32강에 확장합니다. V1 월드컵 로직은 순수성과 결정 가능성을 보강해 이때 이관합니다.

### 5. 운영 경로

관리자 인증, 콘텐츠 작성, 후보 업로드, 미리보기, 검수, 발행, 숨김, 신고 처리를 추가합니다. 모든 변경은 감사 로그를 남깁니다.

### 6. SEO·분석·공유

메타데이터, OG 이미지, 사이트맵, robots, 구조화 데이터, 퍼널 이벤트를 연결합니다. 스테이징에서 크롤러가 받는 원본 HTML을 검사합니다.

### 7. AdSense 준비

`codex/adsense-progress`의 정책·소개·문의 구조를 V2 문구로 다시 작성합니다. 광고는 다음 검증을 통과하기 전까지 비활성화합니다.

- 공개 콘텐츠 수와 품질을 수동 검수했다.
- 빈 화면·플레이·이동·알림 화면에 슬롯이 없다.
- 개인정보 처리방침과 동의 관리가 실제 동작과 일치한다.
- `ads.txt`의 게시자 ID와 운영 도메인을 확인했다.
- 모바일에서 광고와 선택 버튼이 명확히 분리된다.
- 자동 광고가 금지 화면에 삽입되지 않는지 실기기에서 확인했다.

정책 준수는 코드만으로 보장할 수 없으므로 콘텐츠와 실제 배포 화면을 함께 검토합니다.

## 데이터 이관 도구 규칙

- 기본 실행은 `--dry-run`이어야 합니다.
- 입력 행 수, 성공, 제외, 오류 수를 출력합니다.
- 같은 입력을 두 번 실행해도 중복 생성되지 않아야 합니다.
- 소스 ID와 V2 ID 매핑을 별도 기록합니다.
- 이미지 다운로드는 자동화하지 않고 권리 승인 목록만 처리합니다.
- 적용 전후 샘플과 전체 건수를 비교합니다.
- 실패 시 새로 만든 행만 식별해 되돌릴 수 있어야 합니다.

## 전환과 롤백

1. V2는 별도 스테이징 도메인에서 운영 검증합니다.
2. 기존 도메인의 URL별 301/유지/410 매핑표를 만듭니다.
3. 전환 전 DB 백업과 이전 배포 식별자를 기록합니다.
4. 읽기 오류율, 투표 성공률, 페이지 응답, 색인 상태를 관찰합니다.
5. 치명적 오류 시 DNS/배포 별칭을 V1으로 되돌리고 V2 쓰기를 중단합니다.
6. V2에 기록된 투표는 복구 후 재처리할 수 있도록 보존합니다.

## 완료 후 정리

V2 안정화와 데이터 대조가 끝난 뒤에만 중복 파일과 임시 stash 정리를 제안합니다. 보존 브랜치 삭제는 별도 승인 없이 수행하지 않습니다.
